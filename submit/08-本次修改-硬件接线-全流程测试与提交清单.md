## 第一部分：本次修改

### 1.1 目标与最终数据链路

本次工作把原来的“STM32 单向上传、网页只显示”扩展为真正的手机双向操作：

```text
手机 Chrome 编辑体测值
  → Web Bluetooth 写 FFE1
  → ESP32 GPIO17 / UART2_TX
  → STM32 PA3 / USART2_RX
  → 更新 measurement_record_t
  → STM32 重算 BMI、综合评分，可选写入片内 Flash
  → STM32 PA2 / USART2_TX
  → ESP32 GPIO16 / UART2_RX
  → FFE1 Notify
  → 手机回读并显示/保存历史
```

### 1.2 STM32 修改

涉及：

```text
app/app_statemachine.c
modules/ble/ble.c
modules/ble/ble.h
bsp/uart.c
bsp/uart.h
algorithms/record_codec.c
algorithms/record_codec.h
tests/test_codec.c
```

完成内容：

- USART2 从仅发送扩展为收发，PA3 可接收 ESP32 转发的网页命令；
- 增加 `PING`、`GET CURRENT`、`GET HISTORY`；
- 增加手机写入命令：

  ```text
  SET H  <身高 mm>
  SET W  <体重 g>
  SET F  <体脂率×10>
  SET HR <心率 bpm>
  SET O  <血氧百分数×10>
  SET B  <平衡指数×10>
  SET G  <握力 kg×10>
  SET R  <反应时间 ms>
  APPLY
  SAVE
  ```

- 每条 `SET` 成功后返回 `OK <字段>`，越界或解析失败返回 `ERR ...`；
- `APPLY` 更新当前记录但不写 Flash；
- `SAVE` 更新当前记录并追加设备 Flash 历史；
- 身高/体重写入后由 STM32 重新计算 BMI；综合评分也由 STM32 统一计算，网页不能直接改评分；
- 写回后重新生成记录 CRC，并用冻结二进制帧回传网页；
- 手机写入范围：身高 50～250cm、体重 2～300kg、体脂 0～70%、心率 20～250bpm、血氧 50～100%、平衡 0～1000、握力 0～200kg、反应时间 50～10000ms。

### 1.3 ESP32 BLE 网关修改

涉及：

```text
esp32/ble_gateway/ble_gateway.ino
esp32/ble_gateway/README.md
```

完成内容：

- 广播名固定为 `HealthTerminal-Gateway`；
- Service 为 `FFE0`，Characteristic 为 `FFE1`；
- FFE1 同时支持 `Notify`、`Write`、`Write Without Response`；
- 手机写入 FFE1 的字节原样转发至 STM32 UART2；
- STM32 返回的二进制帧按最多 20 字节拆分为 notification；
- BLE 断开后恢复广播，未连接或未订阅时不缓存旧 UART 数据。

ESP32 仍是透明网关，不解析体测字段、不计算 CRC、不改测量值。

## 第二部分：硬件接线

### 2.1 供电总原则

- STM32、ESP32 和所有传感器必须共地；
- ESP32 建议使用自己的 USB 线供电；
- 不要把已由 USB 供电的 ESP32 `3V3` 再与 STM32 3.3V 电源硬并联；
- UART、I2C 和普通 GPIO 均按 3.3V 逻辑处理；
- 上电或改线前先断电，先检查 VCC/GND，再检查信号线；
- PA13/PA14 必须保留给 SWD 烧录。

### 2.2 烧录与调试接线

| ST-Link | STM32F103C8T6 | 说明 |
| --- | --- | --- |
| SWDIO | PA13 | 调试数据 |
| SWCLK | PA14 | 调试时钟 |
| GND | GND | 必须共地 |
| 3.3V/VTref | 3.3V | 目标电压参考；避免与其他电源冲突 |

调试串口：STM32 USART1 TX=`PA9`、RX=`PA10`，`115200 8N1`。调试文本不得接入 BLE 使用的 USART2。

### 2.3 ESP32 双向 BLE 网关

| 功能 | STM32 | ESP32 | 方向 |
| --- | --- | --- | --- |
| 记录/状态上传 | PA2 / USART2_TX | GPIO16 / RX2 | STM32 → ESP32 |
| 手机命令下发 | PA3 / USART2_RX | GPIO17 / TX2 | ESP32 → STM32 |
| 参考地 | GND | GND | 必须共地 |

两侧参数均为 `9600 8N1`。不得使用 ESP32 GPIO1/GPIO3 代替 GPIO17/GPIO16，否则会与 USB 下载调试串口冲突。

### 2.4 I2C 共享总线

| 模块 | VCC | GND | SCL | SDA | 地址 |
| --- | --- | --- | --- | --- | --- |
| SSD1306 OLED | 3.3V | GND | PB6 | PB7 | `0x3C` |
| MPU6050 | 3.3V | GND | PB6 | PB7 | `0x68` |
| MAX30102 | 按载板规格，优先 3.3V | GND | PB6 | PB7 | `0x57` |

总线为 I2C1 100kHz。只保留一组合适的上拉，建议约 4.7kΩ 到 3.3V；很多模块载板自带上拉，接线前检查。

### 2.5 身高、体重、握力和温度

| 模块 | 模块端 | STM32 | 注意事项 |
| --- | --- | --- | --- |
| HC-SR04 | Trig | PB9 | MCU 输出 |
| HC-SR04 | Echo | PB8 / TIM4_CH3 | PB8 为 5V 容忍脚；可串 330Ω 保护 |
| HC-SR04 | VCC/GND | 5V/GND | 必须与 STM32 共地 |
| 体重 HX711 | SCK | PA1 | 建议模块使用 3.3V |
| 体重 HX711 | DOUT | PB11 | 输入 |
| 握力 HX711 | SCK | PA0 | 建议模块使用 3.3V |
| 握力 HX711 | DOUT | PB10 | 输入 |
| DS18B20 | DQ | PB5 | 约 4.7kΩ 上拉到 3.3V |
| DS18B20 | VCC/GND | 3.3V/GND | 不使用寄生供电便于排障 |

### 2.6 矩阵键盘与反应时间

| 功能 | STM32 引脚 | 接法 |
| --- | --- | --- |
| 键盘 ROW0～ROW3 | PB12、PB13、PB14、PB15 | 行输出 |
| 键盘 COL0～COL3 | PA4、PA5、PA6、PA7 | 列输入上拉 |
| 反应 LED | PB1 | PB1→限流电阻 220Ω～1kΩ→LED→GND |
| 反应按键 | PB0 | PB0→常开按键→GND，内部上拉、EXTI0 |

不同 4×4 键盘排线顺序可能不同，必须先用万用表确认实际行列，不能只按排线外观猜测。

### 2.7 上电前逐项勾选

- [ ] PA13/PA14 未被其他模块占用；
- [ ] STM32 PA2→ESP32 GPIO16；
- [ ] STM32 PA3←ESP32 GPIO17；
- [ ] STM32 与 ESP32 共地；
- [ ] ESP32 独立 USB 供电稳定；
- [ ] OLED/MPU6050/MAX30102 的 PB6、PB7 未接反；

- [ ] HC-SR04 Echo 接 PB8，不接 PA0～PA7；

### 3.5 故障定位顺序

| 现象 | 首要判断 |
| --- | --- |
| 找不到设备 | ESP32 是否广播、是否被另一手机占用、Chrome 权限 |
| 能连接但无 PONG | GPIO17→PA3、共地、两侧 9600 8N1 |
| 有 PONG 但读取无记录 | PA2→GPIO16、当前记录是否有效、是否已订阅 Notify |
| `SET` 后等待 `OK` 超时 | PA3 反向链路、STM32 是否已烧录新版固件 |
| `ERR SET_RANGE` | 输入超出固件范围或网页单位填写错误 |
| 有 `SAVED` 但同步不到 | Flash 存储初始化、记录 CRC、是否重连后重新同步 |
| CRC 错误 | UART 丢字节、调试文本串入 USART2、供电/共地不稳 |
