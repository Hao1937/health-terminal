## 3. 最短演示路径

1. 按 [02-硬件接线与上电检查.md](02-硬件接线与上电检查.md) 接线并上电；
2. 使用 `MODULE_SET=liuyanming` 编译个人模块，或用 `MODULE_SET=full` 编译整机；
3. 通过 OLED 和矩阵键盘分别演示 Balance、Reaction 和 History；
4. 给 ESP32 烧录 `esp32/ble_gateway/ble_gateway.ino`；
5. 手机通过 HTTPS 打开 `web/dashboard.html`，先连接 `HealthTerminal-Gateway`；
6. 在 STM32 选择 `6.Score/Upload → Start`，确认网页收到记录；
7. 在网页编辑一个字段，依次验证 `OK`、`APPLIED`、回读，再用 `SAVE` 验证断电历史保持。

## 4. 重要边界与如实说明

- `MODULE_SET=liuyanming` 只把本人模块编成真实现，其他成员传感器仍可能是桩；完整整机应使用 `MODULE_SET=full`。
- 当前 OLED 字库仅覆盖数字、英文字母和少量符号，不支持中文显示。
- MPU6050 每次名义采样 250 点、约 50 Hz、约 5 秒；OLED 重绘和 I2C 等待可能使实际时长略有变化。
- 平衡等级和反应速度等级是课程演示阈值，不是医学诊断标准。
- 睁眼/闭眼对照目前采用同一 Balance 流程分别测量并人工记录；记录结构中没有同时保存两个条件的独立字段。
- Flash 历史区约可保存 76 条记录，当前没有用户菜单中的“手动清空”功能；写满后整区擦除并从头写。每页固定放置 19 条记录，页尾保留空间。
- 反应模块内部的 16 点即时趋势保存在 RAM，重启后丢失；`History` 页面读取的是 Flash 历史。
- Web Bluetooth 页面使用 `acceptAllDevices: true` 解决部分安卓设备按服务过滤时找不到网关的问题，因此设备列表会显示其他 BLE 设备，必须手动选择 `HealthTerminal-Gateway`。
- 当前源码已包含上述真实现路径，但可审查的真机日志、原始数据和截图仍应按 [06-测试与验收记录.md](06-测试与验收记录.md) 补齐；在证据填写完成前，不将清单项表述为全部验收通过。
- Balance 即时结果页、History 记录页和 Web 看板统一将 `balance_x10` 除以 10 后显示一位小数；原始定点值仍按协议保存和传输。
