## 2. 实际运行结构

当前应用的准确运行关系是：

```text
ST_BOOT
   ↓
ST_MENU
   ├─ ui_flow 内部完成菜单/历史页面导航
   ├─ UI_ACT_MEASURE：在 MENU 中同步执行选择的传感器
   └─ UI_ACT_UPLOAD：评分并进入 ST_RESULT
                          ↓
                     BLE + Flash + OLED（只执行一次）
                          ↓ 任意键
                       ST_MENU
```

`app/app.h` 虽然声明了 `ST_MEASURE` 和 `ST_HISTORY`，当前实现并未进入这两个状态：测量在 `ST_MENU` 内同步执行，历史页面由 `ui_flow` 的内部屏幕状态管理。复现或答辩时应按上述实际结构说明。

## 3. 构建方式

### 3.1 一键准备环境

在仓库根目录执行：

```powershell
.\scripts\bootstrap.ps1
```

或按项目文档单独获取 HAL。`core/STM32CubeF1/` 是外部依赖，不提交到 Git。

### 3.2 Host 测试

```powershell
cmake --preset host
cmake --build --preset host
ctest --preset host --output-on-failure
```

Host 测试覆盖纯算法与数据协议，不覆盖 OLED、键盘、EXTI、Flash、MPU6050 I2C、ESP32 和 Web Bluetooth 真机链路。

### 3.3 编译本人模块

```powershell
cmake --preset stm32 -DMODULE_SET=liuyanming
cmake --build --preset stm32
```

此配置启用真实现：

```text
oled keypad reaction ble storage mpu6050
```

其他成员模块会进入 `HS_NOT_IMPLEMENTED` 桩，因此部分测量字段可能显示 `--`。

### 3.4 编译整机

```powershell
cmake --preset stm32 -DMODULE_SET=full
cmake --build --preset stm32
```

固件产物：

```text
build/stm32/firmware.elf
build/stm32/firmware.bin
build/stm32/firmware.hex
```

固件版本或 `MODULE_SET` 改变后，应重新运行 CMake 配置命令，不能只执行 build。

### 3.5 烧录 STM32

```powershell
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/stm32/firmware.elf verify reset exit"
```

## 4. 上电与自检

`app_init()` 的初始化顺序为：

```text
GPIO → DWT delay → USART1/USART2 → I2C1
→ OLED → Keypad → BLE → Storage → BOOT
```

调试串口：

```text
USART1：PA9 TX / PA10 RX，115200 8N1
```

BLE 二进制串口：

```text
USART2：PA2 TX / PA3 RX，9600 8N1
```

USART1 的 `printf` 文本与 USART2 的二进制记录互相独立。

## 5. 完整演示建议

按以下顺序演示，可最大限度减少连接时序问题：

1. 上电后确认 OLED 出现根菜单；
2. 验证 `C/D` 移动、`A` 进入、`B` 返回；
3. 进入 `3.Balance → Start`，完成平衡测试；
4. 进入 `5.Reaction → Start`，完成反应测试；
5. 进入 `7.History`，查看最新记录、详情与趋势；
6. 先在手机网页连接 `HealthTerminal-Gateway` 并等待“已连接”；
7. 再在 STM32 进入 `6.Score/Upload → Start`；
8. 对比 OLED 结果和网页卡片。

## 6. 当前实现的已知限制

- `bodyfat_x10` 当前没有由 app 流程赋值，按现有流程必然保持 `HS_VALUE_INVALID`，网页显示 `--`。
- `Score/Upload` 进入结果页时只发送一次 BLE，不做 ACK、离线缓存或自动重发。
- App 仅在 Score/Upload 结果页保存当前综合记录；Balance/Reaction 的即时结果不会单独追加部分记录。
- BLE 和 storage 返回值在结果页被忽略，当前没有面向用户的发送/写入失败提示。
- timestamp 是设备上电后的秒数，不是 RTC 日期时间。
- MPU6050 与 Reaction 测量期间存在同步等待，会暂时阻塞菜单主循环。
