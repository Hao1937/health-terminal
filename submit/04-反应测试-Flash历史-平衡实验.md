# 反应测试、Flash 历史与平衡实验

## 1. 反应时间测试

### 1.1 硬件与计时

```text
提示 LED：PB1，高电平点亮
独立按键：PB0，内部上拉，按下接地
中断：EXTI0，下降沿
计时：HAL_GetTick()，单位 ms
```

这是毫秒级 SysTick 计时，不是微秒级定时器输入捕获。

### 1.2 流程

1. 如果测试开始时按键仍按住，OLED 显示 `RELEASE BUTTON`；
2. 进入等待阶段，显示 `WAIT FOR LED / DO NOT PRESS`；
3. 等待 `1000 + HAL_GetTick() % 2000` ms，即约 1000～2999ms；
4. 等待期间按键判为 `FALSE START`，返回 `HS_UNSTABLE`；
5. LED 点亮时记录 `t0`，OLED 显示 `PRESS NOW`；
6. EXTI0 回调记录第一次有效按下时刻 `t1`；
7. 结果为 `t1 - t0`，单位 ms；
8. 超过 3000ms 未按下，显示 `TIMEOUT`，返回 `HS_TIMEOUT`；
9. 成功后显示数值与最近测试趋势。

EXTI 中断使用 20ms 去抖，只锁存第一次有效按下。

### 1.3 显示等级

```text
< 150 ms       FAST
150～300 ms    GOOD
> 300 ms       SLOW
```

这只是课程演示分级，不是医学或专业竞技测评标准。“随机等待”也只是系统 tick 取模，并非密码学或统计意义上的真随机。

### 1.4 两种趋势来源

- 反应模块自己的即时趋势：RAM 中最近 16 次，重启丢失；
- `History` 页面趋势：Flash 历史记录中的 `reaction_ms`，重启保留。

### 1.5 复现

1. 进入 `5.Reaction → Start`；
2. 等 LED 亮后再按 PB0；
3. 记录 OLED 的时间和等级；
4. 重复两次，确认趋势出现；
5. 在 LED 亮前故意按一次，确认 `FALSE START`；
6. LED 亮后不按，确认约 3 秒后 `TIMEOUT`；
7. 检查长按、抖动不会生成多次结果。

## 2. 片内 Flash 历史记录

### 2.1 物理区域

链接脚本把 STM32 末 4KB Flash 隔离为 EEPROM 模拟区：

```text
0x0800F000 ～ 0x0800FFFF
4 页 × 1024 字节
代码区限制为前 60KB
```

每条 `measurement_record_t` 固定 52 字节，包含记录 CRC。按当前容量公式：

```text
19 条/页 × 4 页 = 76 条
```

记录按页分组存放：每页固定 19 个槽，槽地址为 `page * 1024 + slot_in_page * 52`，页尾保留空间，不跨页占用下一页槽位。

### 2.2 工作方式

- `storage_init()`：从槽 0 开始扫描连续有效记录，遇到第一个无效 CRC/擦除槽停止；
- `storage_append()`：复制记录，调用 `record_finalize()` 后顺序写入；
- `storage_read(0)`：读取最旧记录；
- UI History：通过倒序索引默认先展示最新记录；
- 写满 76 条：依次擦除 4 页、计数清零、从头写。

当前不是逐条淘汰最旧记录的完整环形缓冲，也不追求工业级磨损均衡。

### 2.3 当前限制

- 没有 `storage_clear()`；
- 菜单没有“手动清空历史”；
- 写入中途掉电可能留下半写槽；
- 下次启动会把第一个坏槽作为有效前缀边界，不修复其后内容；
- App 仅在 Score/Upload 结果页保存当前综合记录；Balance/Reaction 的即时结果不会单独追加部分记录。

### 2.4 复现

1. 记录上电后 `History` 的数量；
2. 完成 Balance 或 Reaction；
3. 进入 `Score/Upload` 完成一次上报；
4. 检查 History 数量变化和最新记录；
5. 断电重启；
6. 再进入 History，确认已有记录和 CRC 仍有效；
7. 对照串口、OLED 与网页；Balance 即时结果页、History 和 Web 均按 `balance_x10 / 10` 显示一位小数。

## 3. MPU6050 平衡晃动指数

### 3.1 初始化

驱动执行：

1. probe `0x68`；
2. 校验 `WHO_AM_I == 0x68`；
3. 软件复位；
4. 选择 X 轴陀螺作为时钟；
5. `CONFIG=0x03`；
6. `SMPLRT_DIV=19`；
7. 陀螺量程 ±250°/s；
8. 加速度量程 ±2g；
9. 初始化 pitch/roll 互补滤波，`alpha=0.98`。

### 3.2 采样与算法

```text
名义采样率：约 50Hz
样本数：250
名义窗口：约 5 秒
```

每帧读取加速度 `ax/ay/az` 和陀螺 `gx/gy`。加速度角：

```text
pitch = atan2(ax, sqrt(ay² + az²))
roll  = atan2(ay, az)
```

再与陀螺积分通过互补滤波融合。`balance_index()` 分别求 pitch、roll 的总体标准差：

```text
balance_x10 = (σpitch_x100 + σroll_x100) / 10
```

数值越低表示该次测试期间晃动越小。协议字段名为 `balance_x10`；OLED 即时结果页、History 和网页统一除以 10 显示一位小数，实验表仍记录原始 `balance_x10`。代码显示等级：

```text
<= 30    GOOD
<= 60    NORMAL
<= 100   WEAK
> 100    RISK
```

这些等级未做医学标定，只作为课程展示。

### 3.3 OLED 流程

```text
BALANCE TEST
FIX ON WAIST
KEEP STILL
READY 3 → 2 → 1
TESTING BALANCE + 进度条
BALANCE RESULT + 等级
```

每约 25 个样本更新一次进度，即约 10%。测试期间采用同步采样，菜单会暂时阻塞。

### 3.4 尚未实现的高级能力

- 陀螺静态零偏标定；
- 加速度六面校准；
- 安装角自动校准；
- 温度补偿；
- MPU INT 引脚采样、DMA 或后台非阻塞采样；
- 跌倒检测；
- 医学诊断。

## 4. 睁眼/闭眼对照实验

### 4.1 目的

在相同站姿和佩戴方式下比较睁眼与闭眼时的平衡晃动指数。闭眼可能减少视觉反馈，从而使晃动指数上升；实际结果以重复测量数据为准。

### 4.2 安全要求

闭眼测试存在失衡风险：

- 必须有一名保护人员站在受试者旁边；
- 选择平整、无障碍、远离台阶的区域；
- 受试者感觉不适立即停止；
- 不建议有眩晕、平衡障碍或近期下肢损伤者自行测试；
- 不用单次结果作医学判断。

### 4.3 统一条件

- MPU6050 固定在腰部，方向和松紧保持不变；
- 双脚位置在地面做标记；
- 双臂自然下垂；
- 每次采样约 5 秒；
- 每个条件建议重复 3 次；
- 每次间隔约 30 秒；
- 为降低顺序效应，可采用 `睁-闭-睁-闭-睁-闭` 交替顺序；
- 不允许在两次测试之间重新安装传感器。

### 4.4 操作步骤

1. 固定 MPU6050，受试者站到标记位置；
2. 进入 `3.Balance → Start`；
3. 睁眼注视前方固定点，完成第一次测试；
4. 记录 `balance_x10`；
5. 休息约 30 秒；
6. 保护人员到位，受试者闭眼；
7. 再次进入 `3.Balance → Start`；
8. 记录闭眼值；
9. 每个条件至少完成 3 次；
10. 分别计算睁眼、闭眼均值，并比较差值或比值；
11. 保存每次测试的逐次原始值、测试顺序和异常备注，不能只保存两张结果照片或最终平均值。

可补充：

```text
差值 = 闭眼均值 - 睁眼均值
比值 = 闭眼均值 / 睁眼均值
```

### 4.6 无效试验条件

出现以下任一情况应作废并重测：

- 测试中移动脚位；
- 扶墙、扶人或迈步；
- MPU6050 松动或方向改变；
- 显示 `MPU TIMEOUT`、`I2C READ FAIL` 或 `SAMPLE ERROR`；
- 测试期间受到明显碰撞或外部干扰。

### 4.7 结果边界

当前 `measurement_record_t` 只有一个 `balance_x10`，代码没有“睁眼/闭眼”条件标签，也不能在一条记录中同时保存两种结果。因此本实验需要人工记录测试条件，或在后续版本扩展记录结构；扩展冻结结构必须经团队评审并同步网页解析。
